# Windows 11 探测脚本 — 使用说明（Phase 4 Stage A）

> 这一步**只是采集信息**，不安装任何东西，也不修改这台机器上的任何设置。
> 现在还**没有** Windows 版本可以安装；我们先要弄清楚你的机器是什么情况。

## 一、要做什么

1. 把 `probe-windows.ps1` 复制到这台 Windows 11 电脑上（放桌面就行）；
2. 在**普通用户**下打开 PowerShell（**不要**用“以管理员身份运行”）；
3. 执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\probe-windows.ps1
```

4. 它会在脚本旁边生成一个 `out\civic-work-desk-windows-probe-<时间>.txt`；
5. 把那个 txt 回传。

就这些。大约十几秒。

## 二、它会不会动我的电脑

不会。脚本被刻意写成只读：

- **不需要管理员权限**。如果弹出了 UAC 提权框，说明有问题，请停下来告诉我们；
- 不安装、不下载、不修改任何程序；
- 不改注册表、不改防火墙、不改端口保留、不改浏览器设置；
- **不读浏览器的任何数据** —— 不读 Cookie、历史记录、书签、密码、配置文件；
- 不读你的任何文档；
- 不联网，所有检查都在本机完成；
- 两次“能不能占用 8765 端口”的测试，占用后**立即释放**，不会留下后台进程。

会写入磁盘的只有两类东西，都写在这里说清楚：

1. 它自己生成的那份 txt 报告（在脚本旁边的 `out\` 目录里）；
2. 为了测“这个目录能不能写”，它会在**每一个被检查的目录**里建一个几字节的空文件、
   然后**立即删掉**。被检查的目录包括临时目录、桌面、开始菜单、下载、用户目录和
   `AppData`。文件名形如 `.civic-probe-<随机串>.tmp`，用完即删，不留残留。
3. 为了测“不用管理员权限能不能建目录联接（junction）”，它会在**临时目录**里建一个
   `civic-probe-<随机串>\` 文件夹，测完连同里面的内容一起删掉。

除此之外不写任何文件，也不改任何已有文件。

## 三、报告里有什么

机器和软件的事实：Windows 版本与内部版本号、架构（是否 ARM64）、PowerShell 版本、
可用命令、可写目录、已安装浏览器的**版本号和路径**、默认浏览器关联、8765 端口是否空闲、
该端口是否被系统保留，以及能否以普通用户身份监听本机回环地址。

报告末尾有一段 `SUMMARY`，把影响决策的几行集中列出，便于比对多台机器。

**里面有你的计算机名和账号名**（路径里会出现，例如 `C:\Users\<你的账号>\...`）。
如果不方便外传，回传前自己把账号名替换掉即可——技术结论不依赖它。

报告里**没有**：浏览器数据、文档内容、任何文件的内容、任何密码或密钥。

## 四、怎么读那些方括号标记

每一行前面都有一个标记，含义是固定的：

| 标记            | 含义                               |
| --------------- | ---------------------------------- |
| `[PASS]`        | 我们希望成功的操作，成功了         |
| `[PRESENT]`     | 这个东西存在／可用                 |
| `[NOT PRESENT]` | 这个东西不存在                     |
| `[DENIED]`      | 权限或策略不允许                   |
| `[IN USE]`      | 资源被别的程序占用了               |
| `[INFO]`        | 只是一条事实，没有成败之分         |
| `[ERROR]`       | 这项检查本身没跑成，后面附报错原文 |

**`[NOT PRESENT]` 和 `[DENIED]` 也是有效结果**，不是脚本坏了。那些都是**测量结果**，
正是我们要知道的东西；脚本遇到这些会继续往下跑，不会中断。

特别是第 8、9 节那两个端口测试：其中一个 `[DENIED]`、另一个 `[PASS]`，是完全正常的情况，
也正是这次探测要回答的核心问题。请**不要**为了让它显示 `[PASS]` 而改用管理员身份重跑——
那样测到的就不是我们要的结论了。

## 五、如果脚本根本跑不起来

也请告诉我们，并附上报错原文。常见原因：

- 组策略禁止运行脚本（`ExecutionPolicy` / AppLocker）；
- 企业安全软件拦截。

这同样是我们需要知道的事实——它会直接影响 Windows 版本用什么方式做。

## 六、现在不承诺什么

Windows 兼容性**尚未验证**。这次探测之后，我们才会根据实测结果决定用哪种本地服务方式，
然后才有可安装的版本。在那之前，任何“支持 Windows”的说法都还不能讲。

这一阶段也**不测**浏览器的离线能力（Service Worker、IndexedDB、Cache Storage 等）：
那些必须由真正的本地服务在 `http://127.0.0.1:8765/` 上提供页面才能测，属于下一阶段。
