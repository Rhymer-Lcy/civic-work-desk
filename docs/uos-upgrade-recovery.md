# UOS 升级、回滚与卸载

> **状态：Stage B 实现完成，命令已可用。**
> 最终安装形态尚未在目标机验证；升级与回退的实测项见 `docs/uos-final-acceptance.md`。

## 一条贯穿始终的原则

**程序文件可以换，来源不能换。**

升级、回滚、重装，都必须继续使用同一个规范地址 `http://127.0.0.1:8765/`。
换了地址就是换了数据库，用户会看到一个空的应用——那不是数据丢失，但后果一样严重。

## 升级

版本目录 + `current` / `previous` 两个指针：

```
releases/2026.09.23-1/
releases/2026.10.05-1/
current  -> releases/2026.10.05-1
previous -> releases/2026.09.23-1
```

做法就是运行新包里的安装程序：

```sh
sha256sum -c civic-work-desk-uos20-loongarch64-<新版本>.tar.gz.sha256
tar -xzf civic-work-desk-uos20-loongarch64-<新版本>.tar.gz
cd civic-work-desk-uos20-loongarch64-<新版本>
sh install.sh
```

它按顺序做这些事，任何一步不过就停下，并且**不会**动已在使用的版本：

1. 用包内 `SHA256SUMS.txt` 校验整包；
2. 停止本程序自己的服务（它持有旧文档根目录）；
3. 复制到新的版本目录，**再校验一遍复制结果**（源文件对不等于写盘对——短写和磁盘满都只在这一步
   能看出来）；校验失败就删掉新目录，原版本不受影响；
4. 安装/更新五个命令与运行库；
5. `previous` 指向旧版本，`current` 指向新版本，**两个指针都读回核对**；
6. 更新菜单项，并确认模板占位符全部替换（没替换的话点菜单会毫无反应）；
7. 清理「当前」「上一个」之外的旧版本目录，每删一个都打印出来；
8. 启动服务并跑一次健康检查。

### 为什么升级必须重启服务

BusyBox httpd **在启动时解析一次文档根目录**（实测：把 `current` 指到另一个版本后，仍在运行的
服务继续提供旧目录的文件）。所以不重启就还在服务旧版本。

安装程序会重启。万一没重启——比如手工改了指针——启动器的健康检查会发现「服务的版本 ≠ 当前版本」
并自动重启自己的服务；`civic-work-desk-status` 也会明确报「不一致」。

### 如果升级时浏览器还开着旧版本

应用自带更新机制：Service Worker 发现新版本后，页面顶部出现「有新版本可用」和「应用更新」按钮，
点一下就重新加载到新版本。也可以关掉标签页，从菜单重新打开。

**不要为了「确保生效」去清除浏览器缓存**——那会连带影响用户数据所在的站点存储。
真的需要一个确定动作时，用浏览器的强制刷新（Ctrl+Shift+R）：它只绕过 HTTP 缓存，不碰站点数据。

## 回滚

**代码回滚和数据回滚不是一回事。**

```sh
civic-work-desk-rollback
```

它把 `current` 与 `previous` 互换、重启服务、再跑一次健康检查；两个指针同样读回核对。
互换而不是单向覆盖，所以回滚之后还能再滚回来。

不能做的：把数据库降级。本产品**不实现**数据库降级。

因此规则是：

- 只有当旧版本与当前数据库结构兼容时，才允许回滚；
- 未来一旦出现数据库迁移，跨过该迁移的回滚就不再安全，届时发布说明会明确写出「此版本之后不可
  回滚至 X 之前」；
- 判断不了的时候，正确做法是导出 JSON 备份，而不是赌一次回滚。

只保留一个可回退版本。要回到更早的版本，重新安装那个版本的包。

## 卸载

```sh
civic-work-desk-uninstall
```

默认卸载**只**删除：五个命令、菜单项、版本目录与运行库、运行时 PID、本部署的日志。

默认卸载**不会**删除：

- 360 浏览器配置；
- 浏览器里的 CivicWorkDesk 数据（IndexedDB，来源 `http://127.0.0.1:8765/`）；
- 你下载的 JSON 备份；
- 你导出的报表。

卸载结束时会明确提示：**浏览器中仍然保留着本应用的数据**。想彻底清除的话，在浏览器的站点数据
设置里删除该来源，或者重装后使用应用内「设置 → 危险操作 → 清空全部本机数据」。
卸载脚本不会替你做这件事——自动清除浏览器数据风险太高，而且不可撤销。

所以：**卸载后重装同一个地址，原来的记录还在。** 这是设计如此，不是残留。

## 什么时候该先备份

以下每一项之前，都先导出一份 JSON 备份：

- 升级或回滚 CivicWorkDesk；
- 重装或重置 360 浏览器；
- 清理浏览器站点数据；
- 系统维护、重装、换机；
- 任何你不确定后果的操作。

导出备份只要几秒钟，而它是唯一能跨浏览器、跨机器恢复的东西。
