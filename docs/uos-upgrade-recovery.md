# UOS 升级、回滚与卸载

> **状态：Stage A 设计。** 具体命令在最终启动器实现之后补齐（Stage B）。
> 本文件先把规则定下来，因为这些规则决定了实现怎么写。

## 一条贯穿始终的原则

**程序文件可以换，来源不能换。**

升级、回滚、重装，都必须继续使用同一个规范地址 `http://127.0.0.1:8765/`。
换了地址就是换了数据库，用户会看到一个空的应用——那不是数据丢失，但后果一样严重。

## 升级

版本目录 + `current` 指针：

```
releases/2026.09.22-a/app/
releases/2026.10.05-b/app/
current -> releases/2026.10.05-b
```

步骤：

1. 解压新版本到 `releases/<新版本>/`；
2. 校验哈希、确认结构完整（缺 `index.html` 就算不完整）；
3. 切换 `current` 指针；
4. 重启本地服务——**必须重启**，因为服务在启动时解析文档根目录，不重启还在服务旧文件；
5. 在浏览器里刷新。

升级**不会**动 IndexedDB，**不会**新建浏览器配置，**不会**清除 Service Worker 或 Cache Storage。

### 如果升级时浏览器还开着旧版本

应用自己有更新提示机制（Service Worker 检测到新版本后，页面顶部出现「有新版本可用」和
「应用更新」按钮）。这套机制在升级后继续有效：用户点一下就会重新加载到新版本。

不要为了「确保生效」去清除浏览器缓存——那会连带影响用户数据所在的站点存储。

## 回滚

**代码回滚和数据回滚不是一回事。**

可以做的：保留上一个版本目录，把 `current` 指回去，重启服务。
不能做的：把数据库降级。本产品**不实现**数据库降级。

因此规则是：

- 只有当旧版本与当前数据库结构兼容时，才允许回滚；
- 未来一旦出现数据库迁移，跨过该迁移的回滚就不再安全，届时发布说明会明确写出「此版本之后不可
  回滚至 X 之前」；
- 判断不了的时候，正确做法是导出 JSON 备份，而不是赌一次回滚。

## 卸载

默认卸载**只**删除：启动器、菜单项、版本目录、运行时 PID 与日志。

默认卸载**不会**删除：

- 360 浏览器配置；
- 浏览器里的 CivicWorkDesk 数据（IndexedDB）；
- 你下载的 JSON 备份；
- 你导出的报表。

卸载结束时会明确提示：**浏览器中仍然保留着本应用的数据**。想彻底清除的话，用应用内
「设置 → 危险操作 → 清空全部本机数据」，或者在浏览器的站点数据设置里手动删除该来源的数据。
卸载脚本不会替你做这件事——自动清除浏览器数据风险太高，而且不可撤销。

## 什么时候该先备份

以下每一项之前，都先导出一份 JSON 备份：

- 升级或回滚 CivicWorkDesk；
- 重装或重置 360 浏览器；
- 清理浏览器站点数据；
- 系统维护、重装、换机；
- 任何你不确定后果的操作。

导出备份只要几秒钟，而它是唯一能跨浏览器、跨机器恢复的东西。
