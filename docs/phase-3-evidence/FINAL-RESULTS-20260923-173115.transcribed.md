## Port conflict

The launcher **refused to start** rather than changing origin or terminating the occupant, and the
service recovered normally afterwards. That is the designed behaviour: a different port would be a
different IndexedDB namespace, which presents to the user as data loss.

## Reading notes

- `httpd.log` being empty is expected and desired: BusyBox httpd is deliberately run without `-v`, so
  request paths are never recorded. An empty log is **not** a failure — the RC1.1 manual's contrary
  wording was corrected in Stage B.
- Paths are shown with the account name redacted to `<user>`.
