# UOS 部署说明

> **当前状态：Stage B。** 服务方案已根据目标机实测证据选定（BusyBox httpd），安装形态已实现。
> **但最终安装形态尚未在那台工作站上验证**，所以仍不得声称「已支持该工作站」。
> 待验收项见本文第八节与 `docs/uos-final-acceptance.md`。

## 一、四样东西，不要混为一谈

部署出问题时，绝大多数误解来自把下面四样东西当成一样东西：

|              | 是什么                           | 在哪里                                | 删掉会怎样               |
| ------------ | -------------------------------- | ------------------------------------- | ------------------------ |
| **构建机**   | 装着 Node 24 / npm 11 的开发电脑 | 不在这台工作站上                      | 与工作站无关             |
| **程序文件** | 构建产物（HTML/CSS/JS），只读    | `$HOME/.local/share/civic-work-desk/` | 程序打不开，**数据还在** |
| **业务数据** | 你录入的工作记录、荣誉、进展     | **浏览器**的 IndexedDB 里             | **数据没了**             |
| **备份文件** | 应用导出的 JSON                  | 你的下载目录                          | 失去可移植的恢复手段     |

一句话：**复制或删除程序目录，既不会备份也不会删除你的数据。**
唯一可移植的备份，是应用里「设置 → 数据与备份 → 导出 JSON 备份」生成的那个文件。

## 二、目标机上不需要装什么

不需要 Node、npm、nginx、Docker、Java、数据库、Electron、容器，不需要联网，不需要浏览器扩展，
**也不需要 sudo**，不注册任何系统服务或 systemd 单元。

用的是这台机器上本来就有的东西：

- **BusyBox httpd**（1.30.1，系统自带）提供静态文件；
- **xdg-open** 打开系统默认浏览器（该机为 360 安全浏览器）；
- XDG 用户级目录规范。

**Python 不是运行依赖。** 目标机有 Python 3.7.3，Stage A 曾把它作为备选服务方案，但实测证据
支持 BusyBox，因此正式部署既不安装也不调用 Python。启动器的健康检查也刻意不使用 python3，
以免它变成事实上的依赖。

## 三、固定地址（这一条最重要）

```
http://127.0.0.1:8765/
```

浏览器按「来源」隔离本地数据。来源由 **协议 + 主机 + 端口** 三项共同决定，三项中任何一项不同，
就是另一个存储空间：

- `http://localhost:8765/` —— 不是同一个来源，里面是空的；
- `http://127.0.0.1:8080/` —— 不是同一个来源，里面是空的；
- 换一个浏览器、或换一个浏览器配置 —— 也是空的。

所以启动器、桌面图标、文档里的地址必须**逐字一致**。如果哪天打开应用发现「数据没了」，
第一件事是看地址栏，而不是找备份。

端口 8765 在验收阶段确认空闲后固定下来。**正式使用之后，端口不会自动更换**：
启动时若发现 8765 被占用，启动器会明确报错并停止，**不会**改用另一个端口——那样会打开一个空的
数据库，看起来就像数据丢失。它也**不会**去结束占用端口的进程。

## 四、安装位置

全部在用户自己的目录下，不写系统目录，不需要提权：

```
$HOME/.local/share/civic-work-desk/
  releases/<版本号>/app/        程序文件（只读）
  releases/<版本号>/runtime/    启动器、httpd.conf、菜单项模板
  releases/<版本号>/VERSION
  current  -> releases/<版本号>     当前使用的版本
  previous -> releases/<上一版本>   可回退的上一版本
  lib/civic-lib.sh                  五个命令共用的运行库
$HOME/.local/bin/                   五个命令（见第六节）
$HOME/.local/share/applications/civic-work-desk.desktop
$HOME/.local/state/civic-work-desk/logs/   日志
$XDG_RUNTIME_DIR/civic-work-desk/          运行时状态（PID）
```

**这些目录里没有业务数据。**

安装时只保留「当前」和「上一个」两个版本目录，更旧的会被清理，并且每删一个都会打印出来。

## 五、日常使用

1. 从开始菜单点「政务工作记录台」；
2. 启动器依次：确认程序文件完整 → 取单实例锁 → 检查是否已有本程序的服务在跑 →
   必要时确认端口空闲并启动 BusyBox → **等健康检查通过** → 才打开浏览器；
3. 用完直接关浏览器即可。本地服务留着不影响任何东西，下次打开更快。

**重复点击菜单项是安全的**：`mkdir` 原子锁保证同时点两次不会起两个服务，已在运行且健康的服务
会被复用。

健康检查不是「端口能连上」那么弱，它有三条断言：

1. `/deployment-health.json` 能取到并且写着版本号；
2. 那个版本号等于 `current` 当前指向的版本——所以升级后还在服务旧目录的情况会被发现；
3. 服务给出的 `index.html` 里引用的入口文件，与该版本记录的入口文件一致——这条能挡住
   「服务的是别的目录」和「返回的是 BusyBox 自己的 404 页面」两种伪成功。

启动失败时给出中文错误说明（端口被占、文件缺失、校验不符、服务无响应、版本不一致等），
不会只留一个白屏。

## 六、五个命令

| 命令                        | 作用                                   |
| --------------------------- | -------------------------------------- |
| `civic-work-desk`           | 启动并打开浏览器（菜单项调用的就是它） |
| `civic-work-desk-status`    | 看状态（**出问题先跑这个**）           |
| `civic-work-desk-stop`      | 停止本程序的服务                       |
| `civic-work-desk-rollback`  | 回退到上一个程序版本                   |
| `civic-work-desk-uninstall` | 卸载（**不删**浏览器里的数据）         |

`stop` 只会结束**经 /proc 核对过**属于本部署的进程：命令行是 BusyBox httpd、绑定的是规范地址与
端口、并且文档根目录在本安装目录之内。三条同时成立才动手。它永远不会「找出占着 8765 的那个东西
然后杀掉」——端口不是所有权的证明。

## 七、关于备份，务必记住

业务数据在浏览器里，所以下面这些操作都可能让数据消失：

- 重装或重置 360 浏览器；
- 清除浏览器数据 / 站点数据；
- 换用另一个浏览器或另一个浏览器账户配置；
- 系统重装。

**在做上述任何一件事之前，先导出一份 JSON 备份。** 同样地，在升级 CivicWorkDesk 版本之前，
也建议先导出一份——虽然升级只替换程序文件、不动数据。

升级后**不需要**清除浏览器缓存。应用自带更新提示（页面顶部「有新版本可用」→「应用更新」），
清缓存反而会碰到数据所在的站点存储。
