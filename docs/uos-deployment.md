# UOS 部署说明

> **当前状态：Stage A（未在目标机验证）。**
> 本文件描述计划中的部署形态。服务方案尚未选定，桌面图标尚未安装，兼容性尚未确认——这些都要等
> 那台工作站上的实测结果回来之后才能定。凡是标着「待验证」的地方，现在都**不是**结论。

## 一、四样东西，不要混为一谈

部署出问题时，绝大多数误解来自把下面四样东西当成一样东西：

|              | 是什么                           | 在哪里                                | 删掉会怎样               |
| ------------ | -------------------------------- | ------------------------------------- | ------------------------ |
| **构建机**   | 装着 Node 24 / npm 11 的开发电脑 | 不在这台工作站上                      | 与工作站无关             |
| **程序文件** | 构建产物（HTML/CSS/JS），只读    | `$HOME/.local/share/civic-work-desk/` | 程序打不开，**数据还在** |
| **业务数据** | 你录入的工作记录、荣誉、进展     | **浏览器**的 IndexedDB 里             | **数据没了**             |
| **备份文件** | 应用导出的 JSON                  | 你的下载目录                          | 失去可移植的恢复手段     |

一句话：**复制或删除程序目录，既不会备份也不会删除你的数据。**
唯一可移植的备份，是应用里「设置 → 数据与备份 → 导出 JSON 备份」生成的那个文件。

## 二、目标机上不需要装什么

不需要 Node、npm、nginx、Docker、Java、数据库，不需要联网，不需要浏览器扩展，
**也不需要 sudo**。

用的是这台机器上本来就有的东西：一个静态文件服务（BusyBox 或 Python，待验证选哪个）、
360 浏览器，以及 XDG 桌面规范。

## 三、固定地址（这一条最重要）

```
http://127.0.0.1:8765/
```

浏览器按「来源」隔离本地数据。来源由 **协议 + 主机 + 端口** 三项共同决定，三项中任何一项不同，
就是另一个存储空间：

- `http://localhost:8765/` —— 不是同一个来源，里面是空的；
- `http://127.0.0.1:8080/` —— 不是同一个来源，里面是空的；
- 换一个浏览器、或换一个浏览器配置 —— 也是空的。

所以启动器、桌面图标、文档里的地址必须**逐字一致**。如果哪天打开应用发现「数据没了」，
第一件事是看地址栏，而不是找备份。

端口 8765 是在验收阶段确认空闲后固定下来的。**正式使用之后，端口不会自动更换**：
如果启动时发现 8765 被占用，程序会明确报错并停止，而不是改用另一个端口——那样会打开一个空的
数据库，看起来就像数据丢失。

## 四、安装位置（计划，待验证）

全部在用户自己的目录下，不写系统目录：

```
$HOME/.local/share/civic-work-desk/
  releases/<版本号>/app/     程序文件（只读）
  current -> releases/<版本号>   当前使用的版本
$HOME/.local/bin/civic-work-desk          启动器
$HOME/.local/share/applications/…desktop  开始菜单项
$HOME/.local/state/civic-work-desk/logs/  日志
$XDG_RUNTIME_DIR/civic-work-desk/         运行时状态（PID）
```

**这些目录里没有业务数据。**

## 五、日常使用

1. 从开始菜单点「政务工作记录台」；
2. 启动器检查程序文件、检查端口、必要时启动本地服务、确认服务确实在提供本版本，然后才打开浏览器；
3. 用完直接关浏览器即可。本地服务留着不影响任何东西，下次打开更快。

启动失败时会给出中文错误说明（端口被占、文件缺失、校验不符、服务无响应等），不会只留一个白屏。

## 六、关于备份，务必记住

业务数据在浏览器里，所以下面这些操作都可能让数据消失：

- 重装或重置 360 浏览器；
- 清除浏览器数据 / 站点数据；
- 换用另一个浏览器或另一个浏览器账户配置；
- 系统重装。

**在做上述任何一件事之前，先导出一份 JSON 备份。** 同样地，在升级 CivicWorkDesk 版本之前，
也建议先导出一份——虽然升级只替换程序文件、不动数据。

## 七、现在还不能说的话

以下事项 Stage A **没有**结论，必须等目标机实测：

- 用 BusyBox 还是 Python 提供静态服务；
- BusyBox 给 `.js` 返回的 MIME 类型是否被 Chromium 接受；
- `xdg-open` 是否打开 360 浏览器；
- Service Worker / Cache Storage / `crypto.subtle` 在该浏览器版本上的实际表现；
- 在禁用 GPU 合成的情况下，台账滚动等操作是否流畅。

验收步骤见 `docs/uos-target-acceptance.md`。
