# 中文文案规范（部署与发布层）

本文件是 CivicWorkDesk **部署与发布层**面向用户的中文文案的唯一权威依据。

适用范围：Windows 安装程序、启动器、状态与停止工具、诊断工具、浏览器兼容性检查页、现场试用说明、
GitHub Release 说明，以及 UOS 安装与维护的用户可见文案。

**不适用**于应用内部的产品界面文案（`src/` 下的 UI 文本）——那属于产品 UX，由
[ui-copy-guidelines.md](ui-copy-guidelines.md) 管辖，不在本文件范围内。

当前逐条文案清单见 [user-visible-copy-zh-CN.md](user-visible-copy-zh-CN.md)。

## 0. 三条总原则

1. **不为了措辞好听而削弱技术含义。** 例如“程序不会强行结束无法确认归属的进程”是一条安全承诺，
   不能简化为“程序很安全”。
2. **只声明实现能够证明的事。** 例如安装前检查被拦截时，不能说“系统未被修改”，
   因为安装程序此时已经解压过自己的临时文件。
3. **历史材料保持历史原样。** 冻结的发布包、验收记录、既往证据文件不因本规范而改写。
   本规范只约束**当前**用户可见文案。

## 1. 名称

| 用途                                           | 写法           |
| ---------------------------------------------- | -------------- |
| 面向用户的产品名                               | 政务工作记录台 |
| 技术标识、路径、可执行文件名、进程名、诊断标识 | CivicWorkDesk  |

纯中文短语内部**不加空格**：写“安装政务工作记录台”，不写“安装 政务工作记录台”。
中英文混排时按常规留一个空格：“政务工作记录台 (CivicWorkDesk)”。

## 2. 地址与浏览器来源

| 禁用     | 使用             |
| -------- | ---------------- |
| 规范地址 | **固定访问地址** |

示例：`固定访问地址：http://127.0.0.1:8765/`

解释浏览器存储语义时，使用技术上准确的概念 **浏览器来源（origin）**，标准表述为：

> 工作记录保存在浏览器中，与浏览器来源（origin）http://127.0.0.1:8765/ 关联。
> 更改协议、主机名或端口会改变浏览器来源；更换浏览器或浏览器配置文件也会使用独立的站点存储。

必须区分两件不同的事：

- **改变来源**：协议 / 主机名 / 端口任一改变；
- **改变站点存储容器**：换浏览器，或换同一浏览器的另一个配置文件。

不得暗示安装目录与浏览器数据身份有关。**安装位置可以改变，固定访问地址不可改变。**

## 3. 用户可见术语表

| 禁用                                      | 使用                | 理由                                                           |
| ----------------------------------------- | ------------------- | -------------------------------------------------------------- |
| 规范地址                                  | 固定访问地址        | “规范”在此处对用户无意义                                       |
| 部署集成 / 系统集成项                     | **安装项**          | 面向普通用户；工程英文文档仍可用 deployment integration        |
| 发布完整性                                | **程序完整性**      | 用户关心的是“程序是否完整”，不是发布流程                       |
| 小服务 / 本机服务                         | **本地服务**        | 统一一个词；且本产品不安装 Windows 服务，不得称 “Windows 服务” |
| 把生成的 txt 发回 / 那个文件 / 可以直接发 | **诊断文件（TXT）** | 见 §5                                                          |
| 激活                                      | **启用**            | “激活”在 Windows / 软件授权语境中含义重叠                      |

保留 **启用版本 / 启用校验 / 启用完成**——这些准确描述“切换到某个发布版本”。

## 4. 安全措辞

标准句：

> 程序不会强行结束无法确认归属的进程。

端口冲突的标准表述：

> 端口 8765 已被其他程序占用，政务工作记录台无法启动。
> 程序不会强行结束无法确认归属的进程，也不会改用其他端口。
> 更换端口会改变浏览器来源，原有记录不会在新的来源下显示。
> 请关闭占用该端口的程序后重试。

**不得**出现开发者自言自语式措辞，例如“这是刻意的：错杀一个无关进程的代价比留下一个服务大得多”。
技术诊断语境可写：

> 这是安全设计：无法确认进程归属时，不执行强制终止操作。

## 5. 诊断文件

统一称 **诊断文件（TXT）**。标准指引：

> 如问题仍然存在，请运行“收集诊断信息”，并将生成的诊断文件（TXT）反馈给维护人员。

受邀现场试用的语境中可用“回传”，但**同一文档内只用一种说法**。

## 6. 安装失败与卸载

安装前检查被拦截时，只能声明实现能证明的事：

> 未写入正式安装目录，安装未完成。
> 未创建应用快捷方式，也未启用任何新版本。

卸载提示必须保留这一句（在后果重要处刻意重复）：

> 卸载程序不等于删除数据。

完整说明：

> 工作记录保存在浏览器的站点数据中。卸载不会删除该站点数据，
> 也不会删除已导出的 JSON、Excel（.xlsx）、Word（.docx）文件。

> 若以后使用同一浏览器及同一浏览器配置文件，并通过同一固定访问地址安装兼容版本，原有记录仍可访问。

面向普通用户首次出现时写 `Excel（.xlsx）文件` / `Word（.docx）文件`；技术列表写 `JSON、XLSX、DOCX`。

## 7. 版本回退

> 版本回退只切换程序文件，不回退数据。本产品不支持将数据结构降级到旧版本。

若某个发布执行了数据结构的前向迁移，文档必须明确说明代码回退是否仍受支持。
JSON 备份始终是安全的可迁移恢复手段。

## 8. 代码签名与 SmartScreen

标准表述：

> 当前 RC 候选版本未进行 Authenticode 代码签名，因此 Windows SmartScreen 可能显示来源或信誉提示。
> 该提示本身不能证明程序安全或不安全。
>
> 请仅从项目正式 GitHub Release 获取安装包，并在需要时核对 SHA-256。
> 如有疑虑，请勿安装。
>
> 请勿关闭 Windows Defender 或 SmartScreen。

**不得**写“不是这个程序有问题”“原因是签名证书尚未采购”，也不得建议用户关闭任何安全功能，
更不得暗示 SmartScreen 提示可以证明程序安全。

## 9. 网络与隐私

**不得**写“不联网。所有数据都在本机，程序本身不向外发送任何东西。”——这超出了本程序能担保的范围。

标准表述：

> 安装和使用不依赖互联网。CivicWorkDesk 不会主动向外部服务上传业务数据。
> 浏览器、操作系统及浏览器扩展自身的网络行为不在本程序控制范围内。

验收环境中“CivicWorkDesk 自身零外部请求”的实测结论记录在工程证据中，不写进面向用户的承诺。

## 9.1 诊断文件中的路径

诊断文件是要被普通同事转发的，因此其中的路径必须先做替换：

- 已知用户目录写成环境变量形式：`%LOCALAPPDATA%`、`%USERPROFILE%`、`%APPDATA%`；
- **用户自选的安装目录只保留盘符**，写成 `D:\<CUSTOM_INSTALL_ROOT>`。

不得声称“自定义路径不包含个人信息”。用户完全可能选择
`D:\张三\政务工作记录台` 或 `D:\某单位\李某\CivicWorkDesk`，
一份同时声明“不含账号名”又原样打印这类路径的文件，是在做无法兑现的承诺。

被隐去的信息用路径**特征**代替：盘符、是否含空格、是否含非 ASCII 字符、层级、长度、是否可写。
这些足以定位自定义路径相关的问题，且不指向任何人。
确需完整路径时，作为单独的人工排查步骤获取，不进入默认可转发的诊断文件。

## 10. 标点

面向用户的中文正文遵循 GB/T 15834—2011：

- 引号用 `“”` `‘’`，**不用** `「」`（后者是竖排形式，也是港台日的横排习惯，非大陆规范）；
- 中文句子内使用全角标点；
- 列举中 `以及` 前不加顿号；
- 书名、文件标题用 `《》`。

命令行语法、可执行文件名、URL、哈希值、技术日志保留其自然的 ASCII 写法，不作全角化。
不因本条改写历史材料或代码语法。

## 11. 自动校验

`npm run audit:copy`（[scripts/copy-audit.mjs](../scripts/copy-audit.mjs)）在当前用户可见文件中扫描
上述被淘汰措辞，并校验关键安全语句仍然存在。

对以下三类使用窄白名单：历史文档中引用旧措辞；解释迁移过程的源码注释；不可变的发布证据。
UOS 侧的用词归一化按 [uos-next-maintenance.md](uos-next-maintenance.md) 排入下一次维护发布，
其当前出现次数由该脚本按基线锁定，只减不增。
